# لغت‌نامهٔ دهخدا — برنامهٔ دسکتاپ آفلاین

برنامه‌ای برای ویندوز (و در صورت نیاز مک و لینوکس) که **۳۱۲٬۵۰۷ مدخل** «لغت‌نامهٔ دهخدا» را کاملاً آفلاین جست‌وجو و نمایش می‌دهد. برنامه هیچ تماس شبکه‌ای ندارد؛ پایگاه داده (حدود ۵۸۰ مگابایت روی دیسک) همراه نصب‌کننده می‌آید. حجم نصب‌کننده حدود ۱۰۰ تا ۱۱۰ مگابایت است (تخمین از فشرده‌سازی LZMA همین پایگاه: ۱۰۵ مگابایت؛ خودِ نصب‌کنندهٔ ویندوز را من نساخته‌ام).

> این برنامه یک ابزار مستقل و غیررسمی است و وابسته به مؤسسهٔ لغت‌نامهٔ دهخدا یا دانشگاه تهران نیست. دربارهٔ منبع و مجوز داده، بخش «منبع داده و مجوز» (پایین) را بخوانید.

## امکانات

- **جست‌وجوی هم‌زمان با تایپ** (debounce کوتاه): تطابق کامل ← پیشوندی ← شامل‌شدن، حداکثر ۵۰ نتیجه. روی دیتای کامل، میانهٔ زمان حدود ۰٫۲ و بدترین حالت حدود ۵ میلی‌ثانیه (اندازه‌گیری‌شده؛ جزئیات پایین).
- **جست‌وجوی هوشمند فارسی**: «اب» سرواژهٔ «آب» را هم پیدا می‌کند ولی املای دقیق بالاتر می‌نشیند؛ ي/ك عربی، اعراب، کشیده، ارقام فارسی/عربی/انگلیسی یکسان می‌شوند؛ نیم‌فاصله و فاصله هم‌ارزند.
- **مدخل‌های هم‌املا کنار هم**: همهٔ مدخل‌هایی که یک سرواژه دارند در یک صفحه می‌آیند (گروه‌های بسیار بزرگ مثل «احمد» با ۳٬۰۱۲ مدخل، ۴۰تا۴۰تا صفحه‌بندی می‌شوند).
- **جست‌وجوی متن‌کامل در معنی‌ها** (FTS5) به‌صورت گزینهٔ جدا: «واژه | متن کامل». برای عبارت دقیق، آن را در گیومه بگذارید.
- **متن امن و خوانا**: HTML معنی‌ها پاک‌سازی می‌شود (فقط `span br font b i a` و کلاس لازم)؛ چهار رنگ دیتا (قرمز، آبی، سبز تیره، صورتی) در حالت تاریک هم خوانا هستند.
- **کیبورد**: `Ctrl+K` جست‌وجو · `↑ ↓` انتخاب · `Enter` باز کردن · `Esc` برگشت (دوباره: پاک کردن) · `Ctrl +/−/0` اندازهٔ متن.
- **تاریخچه و علاقه‌مندی‌ها** در فایل‌های جدا (`%APPDATA%\com.example.dehkhoda\user\`)، تم روشن/تاریک/خودکار، اندازهٔ متن، دکمهٔ کپی، صفحهٔ «دربارهٔ برنامه».
- **تراز دوطرفه** برای متن معنی‌ها: انتهای سطرها هم‌سان می‌شود. سطری که با شکست خط تمام می‌شود (مثل هر مصرع شعر) و آخرین سطر هر بند کشیده نمی‌شود و همان‌طور راست‌چین می‌ماند. (فقط CSS است: `text-align: justify` روی `.entry-body`.)
- **همگام‌سازی دستی علاقه‌مندی‌ها و تاریخچه** از راه یک پوشه: دکمهٔ «همگام‌سازی» ← «انتخاب پوشه…» (مثلاً پوشه‌ای داخل Google Drive، OneDrive یا Dropbox) ← از این به بعد هر تغییرِ علاقه‌مندی‌ها یا تاریخچه خودکار در همان پوشه ذخیره می‌شود («ذخیرهٔ خودکار»، پیش‌فرض روشن؛ در پنجره خاموش می‌شود)، و در رایانهٔ دوم «ورودی گرفتن» را بزنید. «خروجی گرفتن» برای نوشتن دستی هم هست. جزئیات در بخش «طراحی».

## ساخت نصب‌کننده (برای کسی که برنامه‌نویس نیست)

دو راه دارید. **راه ۱ ساده‌تر است و چیزی روی رایانهٔ شما نصب نمی‌کند.**

### راه ۱ — ساخت روی سرور گیت‌هاب (GitHub Actions)

۱. در [github.com](https://github.com) حساب رایگان بسازید و یک مخزن **خصوصی (Private)** جدید باز کنید (دلیلِ خصوصی بودن: نصب‌کننده حاوی داده‌های دهخداست؛ بخش «منبع داده و مجوز» را ببینید).
۲. محتوای همین پوشه را در آن بارگذاری کنید (در صفحهٔ مخزن: *Add file ← Upload files*، یا با `git push`). پوشه‌های `node_modules`، `target` و `data` را بارگذاری نکنید؛ در فایل زیپِ تحویلی هم وجود ندارند.
۳. به تب **Actions** بروید ← **Build Windows installer** ← **Run workflow**.
۴. حدود ۲۰ تا ۴۰ دقیقه صبر کنید. وقتی سبز شد، پایین صفحهٔ همان اجرا در بخش **Artifacts**، فایل `Dehkhoda-windows-installer` را دانلود کنید؛ داخل آن `Dehkhoda_0.1.0_x64-setup.exe` است.

> این workflow را روی ویندوز واقعی نتوانستم اجرا کنم؛ اگر اولین اجرا خطا داد، متن خطا را برایم بفرستید.

### راه ۲ — ساخت روی ویندوز خودتان

**پیش‌نیازها (یک‌بار نصب):**

| چه چیزی | از کجا | نکته |
|---|---|---|
| Node.js (نسخهٔ LTS) | <https://nodejs.org> | همراهش `npm` هم نصب می‌شود |
| Python ‏۳٫۱۰ یا بالاتر | <https://www.python.org/downloads> | هنگام نصب حتماً **Add python.exe to PATH** را بزنید |
| Rust | <https://rustup.rs> | فایل `rustup-init.exe`، گزینهٔ پیش‌فرض |
| Microsoft C++ Build Tools | <https://visualstudio.microsoft.com/visual-cpp-build-tools/> | بارگیری چند گیگابایتی؛ در نصب‌کننده «**Desktop development with C++**» را انتخاب کنید (Rust برای لینک کردن به آن نیاز دارد) |
| WebView2 | — | روی ویندوز ۱۰ و ۱۱ از قبل هست |
| Git | <https://git-scm.com> | اختیاری؛ اگر نبود، دیتا به‌صورت ZIP دانلود می‌شود |

بعد از نصب‌ها یک پنجرهٔ **PowerShell تازه** باز کنید (تا PATH به‌روز شود)، وارد پوشهٔ پروژه شوید و این‌ها را اجرا کنید:

```powershell
cd C:\مسیر\پوشه\dehkhoda

python tools\build_db.py      # دانلود دیتا (حدود ۵۲ مگابایت) و ساخت پایگاه؛ چند دقیقه
npm install                   # نصب وابستگی‌های رابط
npm run tauri:build           # ساخت نصب‌کننده؛ بار اول ۱۰ تا ۳۰ دقیقه (Rust همه‌چیز را کامپایل می‌کند)
```

خروجی: `target\release\bundle\nsis\Dehkhoda_0.1.0_x64-setup.exe`

همهٔ این‌ها را یک‌جا هم می‌شود زد (پیش‌نیازها را چک می‌کند و اگر نبود می‌گوید از کجا نصبش کنید):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1
```

> اگر ویندوز هنگام اجرای نصب‌کننده «SmartScreen» نشان داد: چون نصب‌کننده امضای دیجیتال ندارد، *More info ← Run anyway* را بزنید. (امضا گواهی پولی می‌خواهد.)

## اجرا در حالت توسعه

```powershell
python tools\build_db.py      # فقط بار اول (یا وقتی دیتا عوض شد)
npm install
npm run tauri:dev
```

دیدن ظاهر رابط فقط در مرورگر (بدون Rust؛ با ۲۰ مدخل نمونهٔ واقعی):

```powershell
$env:VITE_MOCK = "1"; npm run dev      # سپس http://localhost:1420
```

متغیر محیطی `DEHKHODA_DB` اگر مسیر یک فایل پایگاه را داشته باشد، به‌جای فایل همراه برنامه از آن استفاده می‌شود.

## تست‌ها

```powershell
python -m unittest discover -s tools/tests     # پارسر، نرمال‌ساز، سازندهٔ دیتابیس (۵۰ تست)
cargo test -p dehkhoda-core                    # هستهٔ Rust (۹۹ تست؛ پایگاه آزمایشی کوچک همراه پروژه است)
npm run typecheck ; npm test                   # رابط (۵۷ تست)
npm run build ; cargo test -p dehkhoda-app     # پوسته (۶ تست)؛ به دیتابیس ساخته‌شده و پوشهٔ dist نیاز دارد
```

تست‌های سنگین روی **دیتابیس کامل** (پیش‌فرض اجرا نمی‌شوند؛ حتماً `--release`):

```powershell
cargo test -p dehkhoda-core --release --test full_db -- --ignored --nocapture
```

این‌ها بررسی می‌کنند: نرمال‌ساز Rust و Python روی هر ۳۱۲٬۵۰۷ ردیف دقیقاً یکی است؛ سرعت جست‌وجوی واژه زیر ۵۰ میلی‌ثانیه است؛ صفحه‌بندی گروه‌های بزرگ؛ و قطع شدن جست‌وجوی متن‌کامل قدیمی با جست‌وجوی تازه.

## طراحی (برای کنجکاوها)

**دیتا.** مخزن `nimah79/Dehkhoda-SQL` ‏۳۳ فایل gzip (دامپ MariaDB) است. `tools/dehkhoda_sql.py` آن‌ها را بدون MySQL و با یک توکنایزر می‌خواند (رشته‌های quoted، `\"`، `\'`، `''`، `\n` و …) و به جای رد شدن بی‌صدا از چیز ناشناخته، با شمارهٔ خط و ستون خطا می‌دهد. نتیجه: **۳۱۲٬۵۰۷ ردیف، دقیقاً برابر عدد README مخزن**؛ شناسه‌ها یکتا و بدون جا افتادگی (۱ تا ۳۱۲۵۰۷).

**پایگاه داده** (`src-tauri/resources/dehkhoda.sqlite`، ≈ ۵۸۰ مگابایت، فقط‌خواندنی، `journal_mode=DELETE` تا در پوشهٔ نصب فایل جانبی نسازد):

| جدول | محتوا |
|---|---|
| `words` | `id`، `word`، `word_norm` (نرمال‌شده؛ «آ» جدا می‌ماند)، `word_fold` (آ/أ/إ/ٱ → ا)، `meaning_html`، `meaning_text` (متن خالص نرمال‌شده) + ایندکس روی `word_norm` |
| `heads` | یک ردیف به‌ازای هر سرواژهٔ متمایز (۲۱۵٬۱۲۲ ردیف) — جست‌وجوی واژه فقط روی این جدول کوچک انجام می‌شود |
| `heads_trgm` | ایندکس FTS5 با tokenizer از نوع `trigram` برای «شامل‌شدن» (سریع حتی برای ۳۰۰ هزار مدخل) |
| `words_fts` | FTS5 «بدون‌محتوا» روی `fold(meaning_text)` — فقط نمایه ذخیره می‌شود نه کپی دومِ متن؛ به‌همین دلیل «اب» در متن‌کامل هم «آب» را پیدا می‌کند |
| `meta` | نسخهٔ طرح‌واره/نرمال‌ساز، تعداد ردیف، commit مخزن داده، زمان ساخت (در «دربارهٔ برنامه» دیده می‌شود) |

دو جدول `heads` و `heads_trgm` را من اضافه کردم: بدون آن‌ها «شامل‌شدن» کل ایندکس را پیمایش می‌کرد و ۱۰۰ میلی‌ثانیه طول می‌کشید؛ با آن‌ها بدترین حالت حدود ۵ میلی‌ثانیه است. اگر پایگاه کوچک‌تری می‌خواهید: `python tools\build_db.py --no-fts` (بدون جست‌وجوی متن‌کامل؛ حدود ۶۴ مگابایت کمتر).

**نرمال‌سازی** (`tools/fa_text.py` و `crates/dehkhoda-core/src/normalize.rs`؛ دو پیاده‌سازی مستقل که با ۳۶ بردار دست‌نویس و ۴٬۰۰۰ رشتهٔ تصادفی هم‌خروجی‌اند و روی همهٔ ردیف‌های دیتای واقعی هم یکی بودنشان تست شده): ي/ى→ی، ك→ک، ة/ۀ→ه، حذف همهٔ علامت‌های ترکیبی عربی (اعراب، تشدید، همزهٔ روی حرف U+0654، …)، کشیده، نویسه‌های نامرئی؛ ارقام→ASCII؛ ZWNJ و هر فاصله→یک فاصله؛ لاتین به‌حروف کوچک. دو مورد را به فهرست شما افزودم: «ى» و «ۀ» (چون «ه + همزه» یک‌تکه است). اگر قاعده‌ای را عوض کردید، `NORM_VERSION` را در هر دو طرف بالا ببرید و `python tools\gen_golden.py` و `build_db.py` را دوباره اجرا کنید؛ برنامه با پایگاه ناسازگار شروع نمی‌شود و پیام روشن می‌دهد.

**ترتیب نتایج.** تطابق کامل ← پیشوندی ← شامل‌شدن؛ در هر مرحله «املای دقیق» بالاتر است، بعد کوتاه‌ترها. «شامل‌شدن» فقط برای ۲ حرف و بیشتر انجام می‌شود (تک‌حرفی، تقریباً همه‌چیز را برمی‌گرداند).

**امنیت.** HTML معنی‌ها در Rust با `ammonia` پاک‌سازی می‌شود (در دیتا یک `<a onmouseover="javascript:…">` واقعاً وجود دارد). CSP محدودی در `tauri.conf.json` هست، افزونهٔ شبکه/فایل/لینک فعال نیست و فقط مجوزهای پایهٔ پنجره داده شده است. تنها افزونهٔ به‌کاررفته `tauri-plugin-dialog` برای پنجرهٔ «انتخاب پوشه» است که فقط از سمت Rust صدا زده می‌شود و هیچ مجوزی (`dialog:*`) از آن به رابط داده نشده. خواندن و نوشتن فایل‌های همگام‌سازی را خودِ هسته انجام می‌دهد، فقط در پوشه‌ای که کاربر انتخاب کرده و فقط با نام‌های `dehkhoda-sync-*.json`.

**همگام‌سازی.** برنامه سرویس ابری ندارد و فقط فایل می‌نویسد و می‌خواند؛ رساندن فایل به رایانهٔ دیگر کار پوشهٔ همگام‌شدهٔ Google Drive، OneDrive یا Dropbox (یا حتی یک فلش) است. هر رایانه فقط فایل خودش را می‌نویسد: `dehkhoda-sync-<نام-رایانه>-<شناسه>.json` (شناسهٔ ۸رقمی بار اول ساخته و در `sync.json` کنار تاریخچه نگه داشته می‌شود). پس دو رایانه هیچ‌وقت یک فایل را نمی‌نویسند و سرویس‌های ابری «نسخهٔ تعارضی» نمی‌سازند. «ورودی گرفتن» همهٔ فایل‌های رایانه‌های دیگر را می‌خواند و برای هر واژه «آخرین تغییر برنده است» (دیدن/افزودن در برابر پاک کردن/برداشتن). برای اینکه حذف هم منتقل شود، برداشتن یک علاقه‌مندی یا واژهٔ تاریخچه یک «گور» با زمان خودش در `favorites.json`/`history.json` به‌جا می‌گذارد و «پاک کردن تاریخچه» یک `clearedAt`. هر رویداد تازه زمانی اکیداً جلوتر از هر چیزی می‌گیرد که همان رایانه تا آن لحظه دربارهٔ آن واژه می‌دانسته؛ پس ساعت کمی عقب‌مانده هم حذف را از کار نمی‌اندازد. نتیجهٔ ادغام به ترتیب فایل‌ها بستگی ندارد و تکرارش همان نتیجه را می‌دهد (روی ۴۰۰ حالت تصادفی تست شده)؛ اگر زمان دو تغییر دقیقاً برابر باشد «ماندن» برنده است تا چیزی گم نشود. فایل‌های خراب، ناشناخته یا جدیدتر نادیده گرفته می‌شوند و دلیلشان در پنجره می‌آید؛ هیچ فایلی پاک یا دستکاری نمی‌شود. ساعت رایانه‌ها باید تقریباً درست باشد. فقط علاقه‌مندی‌ها و تاریخچه همگام می‌شوند، نه تنظیمات (تم و اندازهٔ متن مخصوص هر رایانه‌اند). **ذخیرهٔ خودکار:** پس از هر تغییرِ علاقه‌مندی‌ها یا تاریخچه (و پس از انتخاب پوشه یا ورودی‌ای که چیزی را عوض کند) یک نخ پس‌زمینه فایل همین رایانه را می‌نویسد؛ تغییرهای پشت‌سرهم تا ۱٫۵ ثانیه سکوت جمع می‌شوند (حداکثر ۱۰ ثانیه) تا یک نوشتن بشوند، و هنگام بستن برنامه آنچه مانده بی‌درنگ نوشته می‌شود. نتیجهٔ آخرین ذخیره (زمان، یا خطا مثلاً «پوشه در دسترس نیست») در پنجرهٔ همگام‌سازی دیده می‌شود و با تغییر بعدی دوباره تلاش می‌شود. انتخاب روشن/خاموش در `sync.json` می‌ماند. فقط «خروجی» خودکار است؛ «ورودی گرفتن» همچنان دستی است.

**سرعت.** همهٔ جست‌وجوها در Rust (`rusqlite`، SQLite داخل خود برنامه کامپایل می‌شود) و روی چند اتصال هم‌زمان؛ فهرست نتایج مجازی‌شده است.

## عیب‌یابی

| پیام / مشکل | علت و راه حل |
|---|---|
| `linker 'link.exe' not found` | Microsoft C++ Build Tools نصب نیست (جدول پیش‌نیازها). بعد از نصب، PowerShell را ببندید و دوباره باز کنید. |
| `python` شناخته نمی‌شود | هنگام نصب Python گزینهٔ *Add to PATH* را نزده‌اید؛ دوباره نصب کنید، یا به‌جای `python` بنویسید `py`. |
| هنگام `tauri dev/build` خطای «resource path `resources\dehkhoda.sqlite` doesn't exist» | هنوز پایگاه ساخته نشده؛ اول `python tools\build_db.py` را اجرا کنید. |
| برنامه می‌گوید «پایگاه دادهٔ لغت‌نامه آماده نیست» | `python tools\build_db.py` را اجرا کنید (حالت توسعه)، یا اگر با نصب‌کننده نصب کرده‌اید دوباره نصب کنید. |
| `ERESOLVE` یا خطای عجیب در `npm install` | فایل `.npmrc` پروژه را پاک نکنید؛ با `legacy-peer-deps` تنظیم شده است. |
| دانلود دیتا ناموفق | اینترنت/فیلتر؛ مخزن را دستی دانلود کنید و در `data\Dehkhoda-SQL` بگذارید (۳۳ فایل `.sql.gz`)، دوباره اجرا کنید. |
| ساخت نصب‌کننده خیلی طول می‌کشد | کامپایل بار اول Rust طبیعی است؛ دفعه‌های بعد سریع است. فشرده‌سازی LZMA فایل ۵۸۰ مگابایتی هم چند دقیقه می‌برد. |
| «ورودی گرفتن» می‌گوید فایلی از رایانه‌های دیگر پیدا نشد | فقط فایل رایانه‌های *دیگر* خوانده می‌شود. در رایانهٔ دیگر «خروجی گرفتن» را بزنید و صبر کنید تا Google Drive/OneDrive/Dropbox فایل `dehkhoda-sync-….json` را به این رایانه برساند؛ هر دو رایانه باید همان پوشه را انتخاب کرده باشند. |
| در پنجرهٔ همگام‌سازی نوشته «ذخیرهٔ خودکار انجام نشد» | معمولاً پوشه در دسترس نیست (مثلاً Google Drive هنوز وصل نشده یا درایو جدا شده). پوشه را دوباره وصل یا انتخاب کنید؛ با تغییر بعدی خودکار دوباره تلاش می‌شود، یا یک بار «خروجی گرفتن» را بزنید. |

برای ساخت MSI به‌جای NSIS: `npm run tauri:build -- --bundles msi` (ابزار WiX دانلود می‌شود؛ در ویندوز ۱۱ نسخه‌های جدید باید قابلیت VBSCRIPT فعال باشد، به همین دلیل پیش‌فرض را NSIS گذاشتم).

## مک و لینوکس

Tauri هر دو را پشتیبانی می‌کند و کد برنامه ویندوزی نیست؛ ولی من فقط **لینوکس** را آزمودم (کامپایل، تست‌ها و اجرای برنامه). مراحل مشابه است:

```bash
python3 tools/build_db.py && npm install
npm run tauri:build -- --bundles deb,appimage      # لینوکس (پیش‌نیاز: libwebkit2gtk-4.1-dev و آشنایان؛ راهنمای Tauri)
npm run tauri:build -- --bundles dmg               # مک (روی خود مک)
```

## منبع داده و مجوز

- **متن لغت‌نامه:** «لغت‌نامهٔ دهخدا، مؤسسهٔ لغت‌نامهٔ دهخدا، دانشگاه تهران». دیتا از مخزن [`nimah79/Dehkhoda-SQL`](https://github.com/nimah79/Dehkhoda-SQL) گرفته می‌شود که **فایل مجوز ندارد**. من نمی‌توانم تضمین کنم که بازنشر دیتا (مثلاً گذاشتن نصب‌کننده روی اینترنت) مجاز است؛ برای استفادهٔ شخصی مشکلی نیست، ولی پیش از انتشار عمومی خودتان تکلیف را روشن کنید.
- **فونت:** وزیرمتن (Vazirmatn)، مجوز SIL OFL 1.1 — متن مجوز کنار فونت در `src/assets/fonts/OFL.txt`.
- **ابزارها:** Tauri، React، SQLite، ammonia، rusqlite و غیره، هرکدام با مجوز خودشان.
- شناسهٔ برنامه (`identifier` در `src-tauri/tauri.conf.json`) فعلاً `com.example.dehkhoda` است؛ اگر قصد انتشار دارید، آن را عوض کنید.
